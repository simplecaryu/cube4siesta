# Issue #1: cross-pseudo ρ restart via difference density

## Status

**Resolved** — implemented as `Rho.Restart.Diff` (SIESTA patch) +
`cube4siesta convert --diff/--subtract` + `cube4siesta-vasp-diff`.

## Problem

`Rho.Restart` overwrites SIESTA's `DRho` with a total valence density
ρ(r) read from an external .RHOIN file. When the external density was
produced by a DFT code whose pseudopotential partitions the
core/valence boundary differently from SIESTA's .psf, the scalar field
stored in the file is simply **a different physical quantity** from what
SIESTA would itself compute for the same system.

Concrete case (`examples/vsse_openmx/`):

| | OpenMX V_PBE19 | Cornell NNIN `V-gga.psf` |
|---|---|---|
| V valence config | 3s² 3p⁶ 3d³ 4s² | 3d³ 4s² |
| V valence electrons | 13 | 5 |
| ρ(r) contains V 3s/3p peak? | **yes** | **no** |

Result of injecting OpenMX `tden.cube` into SIESTA with the 5-valence
V.psf: ∫ρ dV = 25 e where SIESTA expects 17 e; a crude `--rescale-to 17`
squashes the whole field by 0.68× without removing the localized
semicore peak; the one-shot diagonalization puts the Fermi level at
+30 eV and E_KS off by ~150 eV. Not a file-format issue — the Cornell
.psf loads fine and the baseline SCF converges cleanly.

## Fix — transfer the *difference density*

Decompose ρ_scf(r) = ρ_atomic(r) + Δρ(r):

- `ρ_atomic(r)` (sum of isolated-atom densities) is **strongly
  pseudo-dependent** — it differs by exactly the semicore peak.
- `Δρ(r)` (bonding-induced redistribution) lives in the valence shells
  all reasonable pseudos agree on — **approximately pseudo-independent**.

Cross-code injection then uses

    ρ_target(r) ≈ ρ_atomic^SIESTA(r) + Δρ^source(r)

The atomic part is generated by SIESTA itself from its own .psf (the
`rhoatm` array already present in `dhscf.F`); only Δρ is transferred.

### Pieces

- **SIESTA patch** (`siesta-4.1.5-rho-restart.patch`): fdf logical
  `Rho.Restart.Diff` (default false, only acts with `Rho.Restart`).
  After the external field is loaded, SIESTA adds its own `rhoatm` to
  the diagonal spin components — same pattern as the existing
  deformation-charge branch.
- **`cube4siesta convert --diff`**: convert a source-provided difference
  density (OpenMX writes `*.dden.cube` natively). No rescaling — Δρ
  must stay charge-neutral (the integral is checked to be ~0).
- **`cube4siesta convert --subtract REF`**: build Δρ from two totals
  when the source has no native difference output (subtract the source
  atomic-superposition density).
- **`cube4siesta-vasp-diff`**: VASP helper — subtract an
  ICHARG=1/NELM=0 CHGCAR (atomic superposition) from the SCF CHGCAR.

## Validated outcome

VSSe (valence mismatch, OpenMX NC source), one-shot vs converged
SIESTA baseline with the standard 5-valence V.psf:

| metric | total-ρ restart | diff-ρ restart |
|---|---|---|
| E_KS | −540.9 eV (−696.6 ref) | **−693.1 eV** |
| mean \|Δband\| occupied | 26.9 eV | **0.21 eV** |
| DM relative Frobenius | 1.49 | **0.103** |

When to use which (measured, not guessed):

- **Valence partitions differ** (e.g. semicore in valence on one side):
  use diff mode. Total-ρ collapses; Δρ is the most accurate transfer
  route at the DM level.
- **Valence partitions match**: use plain total-ρ restart. Diff mode
  *degrades* accuracy there (Si DM error 0.21 vs 0.02; SiC one-shot
  −284 vs −264 eV, see `examples/sic_vasp/diff/`) because the
  source-vs-SIESTA atomic-shape difference is pure noise when there is
  no mismatch to fix.
- **PAW sources**: only the total-ρ route is meaningful; PAW
  atomic-superposition densities differ in shape from a
  norm-conserving rhoatm (the VASP V_sv atomic CHGCAR does not even
  integrate to the valence count on the plane-wave grid).

## Out of scope

- Shell-resolved density transfer (would need projectors).
- Full frozen-core reconstruction à la PAW augmentation.
- Direct density-matrix projection is a separate route (PR #4).
